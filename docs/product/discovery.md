# Product Discovery

## Opportunity

Agentic AI demonstrations often optimize for visible generation while leaving safety, delivery controls, evaluation, operations, and cost implicit. A cohesive reference can shorten the path from concept to an evidence-backed engineering decision.

## User problems

- Engineers cannot easily see how agent state, RAG, tools, approvals, and evaluation fit together.
- Reviewers cannot distinguish a claimed capability from a tested one.
- Operators lack a complete execution history when model or tool behavior fails.
- Decision-makers cannot compare quality, latency, safety, and cost in one workflow.

## Hypotheses

1. A deterministic local workflow can teach the architecture without requiring paid services.
2. One end-to-end scenario provides stronger evidence than disconnected technology samples.
3. A capability registry reduces the time required to verify implementation claims.
4. A mandatory approval point makes security and state-management trade-offs concrete.

## Risks

- Scope expands into a commercial platform rather than a reference implementation.
- Framework features obscure domain rules and traceability.
- Simulators are mistaken for verified third-party integrations.
- Cloud infrastructure overwhelms the ten-minute demonstration.
- The capability list becomes documentation without executable evidence.

## Learning plan

- Measure setup success on a clean supported machine.
- Time the main demonstration after setup.
- Verify that a reviewer can explain why a tool action was blocked or allowed.
- Compare the current golden-set report with its baseline.
- Audit a random implemented capability from registry to evidence.
