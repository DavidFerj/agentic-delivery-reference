# Contributing

## Before changing behavior

1. Read `AGENTS.md` and the relevant specification.
2. Identify the affected `FR`, `NFR`, and `AC` identifiers.
3. Preserve existing contracts or document the migration.
4. Add tests for success, failure, boundary, and security behavior.
5. Update `capability-map.yaml` only when evidence exists.

## Pull requests

Keep changes focused. Describe requirements addressed, architecture decisions, validation commands, security considerations, deployment implications, assumptions, and remaining risks. Never include secrets, personal data, or production data.
